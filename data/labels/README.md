# Label data

This is where real, sourced labels live. See [ADR 0002](../../docs/adr/0002-labels-require-a-cited-source.md)
for why every entry here has a `source`, enforced by `@opentrace/core`'s types — there is no
code path that writes a `Label` or `Tag` without one.

## What's here today

- **`ofac-sdn.json`** — generated by `npm run ingest:ofac` (`scripts/ingest-ofac-sdn.ts`). Pulls
  the real, current U.S. Treasury OFAC Specially Designated Nationals (SDN) list and extracts
  every digital-currency address tagged for a chain this project supports (currently Ethereum and
  Solana — OFAC's list also includes Bitcoin, Tron, Monero, and others this project doesn't have a
  chain adapter for yet, so those are skipped, not mislabeled onto the wrong chain).
  - Every entry: `confidence: "verified"` (OFAC's own published, human-curated list — not a
    probabilistic guess), `source.url` pointing at OFAC's sanctions search tool, `source.addedAt`
    set to the date the script last ran.
  - Every sanctioned address also gets a `"sanctioned"` `Tag`, independent of its `Label`.
  - Re-run `npm run ingest:ofac` any time to refresh against the live list — OFAC updates it
    continuously, so a long-stale copy of this file will miss recent designations or (less
    often) include a delisted one.
- **`uk-sanctions-list.json`** — generated by `npm run ingest:uk` (`scripts/ingest-uk-sanctions.ts`).
  Pulls the real, current **UK Sanctions List** (`https://sanctionslist.fcdo.gov.uk/docs/UK-Sanctions-List.csv`,
  linked from [gov.uk/government/publications/the-uk-sanctions-list](https://www.gov.uk/government/publications/the-uk-sanctions-list))
  and extracts every digital-currency address the list explicitly ties to Ethereum or Solana.
  - This *is* the UK's OFSI sanctions data: OFSI's own Consolidated List of Asset Freeze Targets
    (`ConList.csv`) closed on 28 January 2026 and is no longer updated; since then the
    FCDO-published UK Sanctions List is the single source for every UK designation, OFSI asset
    freezes included. The old `ConList.csv` URL still serves a frozen copy — don't use it.
  - Every entry: `confidence: "verified"` (a government-published, human-curated list),
    `source.url` pointing at the FCDO's public search tool, and `source.description` naming the
    UK Sanctions List reference (e.g. `RUS1421`) and regime, so any entry can be checked there.
  - Every sanctioned address also gets a `"sanctioned"` `Tag`. An address on both the OFAC and UK
    lists keeps both tags, each with its own citation.
  - Addresses are free text in the list's "Other Information" column, in several inconsistent
    shapes. The script only takes an address when the text names a supported chain for it — an
    `0x` address listed under BNB, or under no chain at all, is skipped, never guessed onto
    Ethereum. Today the list has no Solana addresses; all labels are Ethereum.
  - Re-run `npm run ingest:uk` to refresh; the FCDO updates the list continuously.
- **`safe-deployments.json`** — generated by `npm run ingest:safe` (`scripts/ingest-safe-deployments.ts`).
  Labels every Ethereum mainnet contract address from Safe's own official deployment list,
  [github.com/safe-global/safe-deployments](https://github.com/safe-global/safe-deployments)
  (MIT-licensed, maintained by Safe's verified GitHub org, the list Safe's own SDKs read their
  contract addresses from). The data originates with the protocol that deployed the contracts,
  not with any labeling platform.
  - Every entry: `confidence: "verified"`, `source.url` pointing at the exact deployment file at
    the exact commit it was read from (so the citation can't drift), and a `"protocol-contract"` `Tag`.
  - The script checks every address on mainnet (`eth_getCode`, via `ETH_RPC_URL` or the public
    endpoint) and refuses to label one with no contract code, so a typo upstream can't become a label.
  - Re-run `npm run ingest:safe` when Safe publishes a new version.

The explorer reads all three files (`packages/features/explorer/src/bootstrap.ts`, via
`CompositeLabelStore`): sanctions lists take priority for the one `Label` an address shows, and
tags from every source are always shown. A new dataset file must be added to that list too.

## Format

A JSON file matching `{ labels: Label[], tags: Tag[], entities: Entity[] }` — see
`packages/core/src/types.ts` and `packages/core/src/store.ts`.

## Adding a new label source

1. Confirm it's genuinely public and checkable — a URL someone else could open, or a named
   document.
2. Write an ingestion script under `scripts/` (follow `ingest-ofac-sdn.ts`'s shape) that produces
   real `Label`/`Tag` entries with that source, or hand-author a small JSON file in this format
   for a one-off batch.
3. If it's large or updates on its own schedule, don't commit the generated output as the only
   copy of truth — commit the ingestion script, and document in this README how/when to re-run
   it, the way `ofac-sdn.json` does above.
4. Never hand-write a `Label`/`Tag` with a placeholder or guessed `source.url` to get past the
   type system — that defeats the entire point of this file. See `CONTRIBUTING.md`.

## Known gaps (real, disclosed)

- Coverage is small — 89 OFAC addresses across two chains, 6 UK Sanctions List addresses (3 of
  them also on OFAC's list), and 52 Safe protocol contracts, from three sources. This is a seed,
  not a claim of comprehensive coverage. Arkham's own labelset took years and 3.9 billion rows; this
  project is one focused day old.
- Stablecoin addresses in the OFAC list (`USDT`/`USDC`) are skipped — OFAC doesn't record which
  chain a stablecoin address is actually on, and guessing would risk mislabeling an address that
  belongs to an unsupported chain as if it were Ethereum or Solana.
